# 데이터·AI 검증 스킬 사용 가이드

Probe 코치가 문제 정의와 진행을 맡고, 아래 스킬은 실제 데이터·구현에서 필요한 근거를 보강한다. 평가항목 연결은 과거 사진에 대한 준비용 해석이며 공식 점수 예측이 아니다. 없는 데이터나 기능을 스킬 사용을 위해 새로 만들 필요는 없다.

## 언제 무엇을 쓰나

| 상황 | 스킬 | 남길 근거 | 관련 평가항목 |
|---|---|---|---|
| CSV·Excel·JSON·표를 처음 받음 | `explore-data` | 데이터 단위, 범위, 결측·중복, 사실과 질문할 가설 | 정보 활용, 문제 상황 및 제약 정의 |
| 분석 수치를 MVP·PPT에 넣기 전 | `validate-data` | 분모·기간·필터·집계 재계산, 주장과 원본의 일치 여부 | 검증 루프, 실무적 품질 위험, 제출물 완성도 |
| 실제 결과를 발표용 차트로 표현 | `data-visualization` | 차트, 원본·집계표, 단위·기간, 표시 확인 | 소통 명료성, 정보 활용, 제출물 완성도 |
| 챗봇·검색·요약 등 AI 기능 구현 | `llm-evaluation` | 시험 사례, 실제 응답, 판정 기준, 변경 전후 비교 | 기능적 정확성, 검증 루프, AI 산출물 동작 및 리스크 예측 |
| 오류가 나거나 수정해도 재발 | `systematic-debugging` | 재현 조건, 원인 가설과 근거, 수정 후 재검증 | 검증 루프, AI 산출물 구조 이해, 실무적 품질 위험 |

## 1. 데이터를 받았을 때

```text
$explore-data
제공된 데이터에서 행 하나의 의미, 식별키, 기간과 단위, 결측·중복을 확인해줘.
전체 데이터와 표본 분석을 구분하고 실제 확인한 결과만 적어줘.
현재 문제와 연결되는 사실, 원인 가설, AI 사원에게 추가로 물어볼 질문을 나눠줘.
기존 brief.md와 evidence.md에 근거 위치를 연결해줘.
```

데이터에 ‘처리 지연’이 보인다는 사실과 그 원인이 ‘인력 부족’이라는 주장은 다르다. 원인 가설은 인터뷰나 추가 자료로 확인한다. 분석을 위해 결측 데이터를 임의로 지우지 않는다.

## 2. AI 기능이 있다면

```text
$llm-evaluation
우리가 만든 AI 기능을 실제로 검증하자.
정상 질문, 자료에 답이 없는 질문, 모호하거나 충돌하는 자료 등
중요한 실패 유형을 포함한 작은 평가 세트를 만들어줘.
기대 동작과 판정 기준을 정한 뒤 기존 모델·설정으로 실행해줘.
같은 입력으로 변경 전후를 비교하고 실제 출력·판정 근거·API 오류·미실행을 구분해줘.
사람 검토와 AI 심사 결과도 구분해서 evidence.md에 연결해줘.
```

이 스킬이 평가하는 대상은 제품의 AI 응답이다. 참가자의 Probe 공식 점수를 계산하지 않는다. 작은 합성 평가 세트의 통과율을 전체 업무 정확도로 발표하지 않는다. API가 준비되지 않았다면 평가 계획까지 만들고 실제 실행은 미실행으로 표시한다.

## 3. 오류가 나면

```text
$systematic-debugging
현재 오류의 재현 조건과 실제 로그부터 확인해줘.
원인 가설과 그 근거를 설명하고 한 번에 한 원인씩 확인하자.
최소 수정 후 같은 조건에서 재검증하고, 해결된 부분과 남은 문제를 기록해줘.
```

오류 원인 설명을 들은 뒤 참가자가 ‘어느 단계에서 왜 문제가 났는지’를 자신의 말로 설명해본다. 수정 성공과 이해 확인은 별도로 기록한다.

## 4. 발표 수치와 주장 점검

```text
$validate-data
발표 초안의 수치와 결론을 원본 데이터·실제 시험 결과에 대조해줘.
분모, 기간, 단위, 필터, 집계 방식을 확인하고 핵심 수치를 재계산해줘.
확인된 주장, 수정할 주장, 근거가 없어 검증하지 못한 주장을 나눠줘.
실제 측정 결과와 목표·합성 데이터 결과를 구분해줘.
```

예를 들어 ‘예시 10건 중 8건 통과’를 ‘업무 정확도 80%’로 바꾸면 평가 범위가 달라진다. 표본·시험 조건과 실패·미실행도 함께 표시한다.

## 5. 검증한 수치를 차트와 PPT로

```text
$data-visualization
검증된 결과를 발표에서 읽기 쉬운 한국어 차트로 만들어줘.
핵심 비교에 맞는 차트를 고르고 출처·기간·단위·표본 크기를 표시해줘.
원본과 집계표, 재생성 코드를 남기고 실제 그림의 한글 표시와 잘림을 확인해줘.
```

그 뒤 PPT가 필요하면:

```text
$slides
확인한 차트와 근거를 발표 PPT에 반영해줘.
차트를 편집할 수 있어야 한다면 집계표로 네이티브 차트를 만들어줘.
실제 측정값·목표값·합성 결과와 남은 한계를 구분해줘.
```

`visual-explainer`는 목표·진행·구조를 보여주는 현황판에, `data-visualization`은 정량 데이터 차트에 사용하면 구분하기 쉽다. 기존 검증·기록 파일을 재사용한다.

## 현장 준비

이 다섯 스킬은 안내와 참고 자료로 설치된다. 데이터 작업은 기존 Python 환경을 사용하고 필요한 패키지만 준비한다. AI 평가의 실제 호출은 프로젝트의 모델·API 환경이 필요하며 외부 평가 서비스 가입을 기본으로 요구하지 않는다. 오류 추적은 기존 로그·테스트 도구를 사용한다. 추가 준비 방법과 원본 예제의 한계는 각 스킬의 `BUNDLE.md`에 있다.
