# 최소 기록과 제출 점검

프로젝트에 비슷한 기록이 있으면 그 파일을 사용한다. 아래는 필요한 기록 구조이며 미리 모든 빈 문서를 만들 필요는 없다. 초기 기록이 없다면 현재 확인할 수 있는 사실부터 적고 과거 대화를 재구성하지 않는다.

Probe 실전 모드에서는 중요한 결정·검증·변경을 현재 평가 대상 대화에서도 짧게 설명한다. 아래 파일은 맥락 보존과 재현을 보조한다. 대화에 이미 남긴 내용을 길게 반복하거나, 별도 파일을 자동 수집되는 대화 기록으로 간주하지 않는다.

## 제출 직전

- 핵심 흐름을 최종 상태에서 다시 실행할 수 있는가?
- 실행 명령·환경 변수 이름·의존성·샘플 입력·예상 출력이 있는가? 비밀키 값은 포함하지 않는다.
- 실제 연동, mock, 미구현을 구별했는가?
- 핵심 요구사항에 출처와 검증 결과가 연결되는가?
- 공식 제출 대상에 필요한 자료가 실제로 들어가는가? 로컬 참고 파일이 자동 채점 대상이라고 가정하지 않는다.
- 실제 측정 결과와 목표·기대 효과를 구분했는가?
- 중요한 미해결 오류와 적용 한계를 설명했는가?
- 참가자가 구조·선택 이유·실패 조건을 자기 말로 설명했는가?

제출물 제안은 문제·근거·실행 방법·검증·한계 중심으로 짧게 만든다. 공식 제출 형식이 주어지면 그 형식을 따른다. 제출 버튼 클릭, 외부 공개, 데이터 전송은 해당 작업에 대한 사용자 요청과 환경의 권한 범위 안에서 수행한다.
