# probe/start — Probe 실전 시작

`probe/start`는 설치된 Probe 코치가 해석하는 **Codex 대화창의 시작 문구**다. 셸 프로그램이나 Codex의 네이티브 슬래시 명령을 등록하는 기능이 아니다. `/probe/start`도 대화 메시지로 전달되면 같은 뜻으로 해석한다. 호스트가 문구를 스킬에 연결하지 못하면 `$probe-hackathon-coach probe/start`로 직접 지정한다.

## 적용할 시작 지침

아래는 사용자가 정한 시작 지침이다. 그대로 재출력하지 말고 이번 과제와 이후 관련 대화에 적용한다.

> Probe 실전 모드로 진행해줘. 제한 시간은 4시간이야.
>
> 먼저 문제와 인터뷰 내용을 확인된 사실·가설·미확인 사항으로 나눠줘.
> 핵심 사용자 흐름 하나와 실행 가능한 완료 기준을 정한 뒤 구현하자.
>
> 작업은 입력·결과물·완료 기준이 드러나게 나누고,
> 중요한 선택에서는 대안과 이유를 설명해 내가 판단할 수 있게 해줘.
> 새 정보가 나오면 목표·범위·검증 기준을 함께 갱신해줘.
>
> 실제로 실행한 검증과 아직 실행하지 않은 검증을 구분해줘.
> 중요한 결정과 검증 결과만 간결하게 기록하고,
> 마지막에는 내가 구조·동작·선택 이유를 이해했는지 질문해줘.

## 시작 응답과 이어가기

1. [실전 대화 지침](dialogue.md)과 [고득점 준비 가이드](score-playbook.md)를 읽는다. 이미 제공된 과제·인터뷰·코드·기록을 먼저 확인하고 같은 정보를 다시 요구하지 않는다.
2. 처음 시작하고 다른 시간 정보가 없으면 **사용자가 정한 기본 작업 시간 4시간**으로 계획한다. 예를 들어 `probe/start 남은 시간 90분`이라고 입력하면 90분을 우선한다. 같은 과제에서 다시 호출하면 기존 진행 상황과 마지막으로 확인된 시간을 이어가며 4시간으로 초기화하지 않는다. 실제 마감이나 경과 시간을 모르면 남은 시간을 추측하지 않는다.
3. 첫 응답에서 적용 사실을 한 줄로 알리고 `현재 단계 / 시간 기준 / 확인된 사실·가설·미확인 사항 / 다음 행동 최대 3개 / 참가자가 지금 할 일 / 구현·검증 상태`를 간결하게 보여준다. 가이드의 시간표는 실제 남은 시간과 이미 완료한 단계에 맞춘다.
4. 과제나 인터뷰가 아직 없으면 현재 단계를 **과제·인터뷰 입력 대기**로 표시하고 과제 안내 또는 AI 사원과의 대화를 보내 달라는 질문 하나로 시작한다. 문제·완료 기준·인터뷰 답변을 지어내지 않는다. 자료가 있으면 근거를 분류하고 핵심 흐름과 완료 기준 제안부터 이어간다.
5. 기존 기록 파일을 재사용하고 중요한 결정·변경·실행 결과만 갱신한다. 구현과 검증 상태를 분리하며, 실행 전에는 미실행으로 표시한다. 마지막 이해도 질문은 한 번에 한 가지씩 묻고 참가자의 답을 기다린다. AI의 설명만으로 참가자가 이해했다고 기록하지 않는다.

이 시작 문구는 설정된 자동 녹화·전송·타이머를 뜻하지 않는다. 실제 Probe 수집 범위와 공식 점수는 확인된 안내 이상으로 단정하지 않는다.
